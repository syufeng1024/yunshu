## 1. 事实（已核，勿重复调查）

| 事实 | 证据 |
| :--- | :--- |
| `t_model` **没有 `max_output_tokens` 列** | `information_schema.columns` 查 `t_model` 只有 `context_length` |
| 但快照结构体有该字段 | `internal/boot/route_snapshot.go:46` `MaxOutputTokens int64 \`json:"max_output_tokens"\`` |
| **该字段从未被赋值** | `grep -n "MaxOutputTokens" internal/boot/*.go` 仅命中第 46 行声明本身；`loadModels` 的 SQL（`:225` 附近）也没选它 |
| 所以快照里恒为 0，`gw.ModelEntry.MaxOutputTokens` 恒 0 | `internal/gw/catalog.go:73` 同名字段由快照 JSON decode 而来 |
| 因此 `p09_estimate.go` 的**第二级兜底永不命中** | `outputTokens()`：`if c.Model.MaxOutputTokens > 0` 永远为假 |
| T44 已把第三级裁到 `min(context_length, 32768)`，故当前不会死锁，但配置能力缺失 | `internal/gw/p09_estimate.go:198-207` |
| 后台 DTO 也没有该字段 | `internal/control/ops/model.go:96` `modelCreateRequest`、`:110` `modelPatchRequest` 均无 `max_output_tokens` |
| 前端模型表单只有上下文长度 | `web/src/pages/admin/ModelsPage.tsx:102/345/359` 只有 `contextLength` |
| `web/src/api/types.ts` 是 **openapi-typescript 生成物，禁止手改** | 文件头注释「auto-generated by openapi-typescript. Do not make direct changes」 |

## 2. 要做（五条，按序）

1. **新增迁移 `0031_add_model_max_output_tokens`**
   - up：`ALTER TABLE t_model ADD COLUMN max_output_tokens INT UNSIGNED NOT NULL DEFAULT 0 AFTER context_length;`（`0` 表示未配置，沿用既有语义）
   - down：`ALTER TABLE t_model DROP COLUMN max_output_tokens;`
   - **必须重生成 `checksums.golden`**：`bash scripts/gen-migration-checksums.sh`
   - **必须同步 `guard_test.go` / `migrate_test.go` 里的迁移版本数与表数断言**（新增一个版本，这些数字会变）
   - 本机跑 `./scripts/dev.sh migrate up` 后在开发库验证列存在；再 `migrate down 1` 验证可逆，然后重新 up

2. **快照带上该列**
   `internal/boot/route_snapshot.go` 的 `loadModels`：SQL 增选 `max_output_tokens`，`rows.Scan` 按列序补 `&m.MaxOutputTokens`。
   **注意 Scan 参数顺序必须与 SELECT 列序严格一致**，错位会静默串值（`context_length` 与 `max_output_tokens` 都是 int 且相邻，最容易串）。

3. **后台接口补齐**
   `internal/control/ops/model.go`：
   - `modelCreateRequest` / `modelPatchRequest` 增 `MaxOutputTokens *int64 \`json:"max_output_tokens"\``
   - 列表/详情视图（`modelView` 或等价结构）增 `max_output_tokens`
   - SELECT 语句增列
   - 校验：`0 <= v <= context_length`（`context_length > 0` 时）；越界 `invalid_field("max_output_tokens")`。`context_length == 0` 时只校验 `>= 0`。**不要**在此硬编码 32768。

4. **openapi 同步**
   `api/openapi.yaml` 的模型创建/编辑 schema 与模型视图补 `max_output_tokens`（integer，`minimum: 0`，描述写清「0 = 未配置，按 `min(context_length, 32768)` 兜底」）。

5. **前端表单 + 类型重生成**
   - 跑 `cd web && npm run gen:api` 重新生成 `src/api/types.ts`（**禁止手改该文件**）
   - `web/src/pages/admin/ModelsPage.tsx` 的模型编辑弹窗增一个「输出上限（max_output_tokens）」数字输入，紧跟「上下文长度」之后；`0` 或留空表示未配置，提交时按 `0` 传
   - 表格列或详情里能看到该值（若现有列布局放不下，可只在编辑弹窗与详情展示，不强求加列）
   - `web/src/pages/admin/ModelsPage.test.tsx` 补断言：表单能渲染该字段、提交体里带 `max_output_tokens`

## 3. 硬约束

1. **不改 `internal/gw/p09_estimate.go`**。T44 已定稿（兜底裁剪到平台上限），本卡只负责让第二级（模型自身上限）真正能取到值。
2. **不改 `internal/gw/catalog.go`**。字段已存在，本卡只负责供数。
3. **迁移必须成对**（up + down 都写），且**新增迁移后必须重生成 `checksums.golden`**。
   ⚠️ 只允许**新增** `0031`，**严禁修改任何已存在的迁移文件**——`migrate up` 会 Verify 已应用版本的 checksum，改老迁移会让所有已部署环境升级被拒（证据：`internal/platform/migrate/migrate.go:143-147`）。
4. **禁止手改 `web/src/api/types.ts`**，必须由 `npm run gen:api` 生成。
5. 迁移里的列类型必须是 `INT UNSIGNED NOT NULL DEFAULT 0`，与既有 `context_length` 风格一致；不要 `NULL`（会让所有消费方多一层判空）。
6. `bash scripts/check-eol.sh` 退出 0；`go build ./...`、`go vet ./...`、`gofmt -l` 干净；`cd web && npm run typecheck` 通过。
7. **不 commit、不 push、不建分支**。
